这一版针对「传得太慢」和「传错了没法停」两个问题。

## 速度

v0.1.3 之前有两处浪费：

1. **单帧被固定卡在 244B。** 手表的 LinkParams 会声明 1022B 的分片大小，适配器协商出的
   ATT MTU 也可能远大于 247。现在按 `MTU - 3` 取单帧上限（Windows 上通过
   `BleakClient.mtu_size` 读取），大 MTU 时一个传输单元能用更少的帧发完。
2. **每一帧都等上一帧写完。** 现在按窗口（默认 8 帧）并发提交写入，让蓝牙栈把一个
   连接事件里能塞的包都塞进去。如果某个适配器/驱动不接受并发 GATT 操作，程序会自动
   退回逐帧发送并在日志里提示，不会因此传坏文件。

进度条现在会显示实时速度：`37% · 21.4 KB/s`。日志里也会每 2 秒记一行
`上传速度 X KB/s`。

**需要说清楚的一点**：真正决定上限的是手表固件。手表用 `0x28/0x05` 告诉手机“下一次给我
多少字节、从哪个偏移开始”，节奏和每段大小都由它决定，手机只能尽快把这一段写完。所以
这一版能保证的是“不浪费带宽”，不能保证速度翻几倍。想确认瓶颈在哪，请复测后把日志发我：

```
蓝牙 MTU 247，单帧最多 244B
传输参数: 单元 200B，分块加密
上传速度 18.6 KB/s
```

勾选「调试日志」还会记录手表每次请求的 `offset` / `size`，据此可以判断是“段太小”
（每段都有一次往返）还是“每帧太大”（加密后被迫拆帧）。

## 取消上传

「开始上传」旁边新增「取消上传」按钮，上传过程中随时可点：

- 立即停止发送，正在写的帧会被中断，剩余排队文件标记为「已取消」
- 手表协议里没有中止命令，所以手表可能还会等几秒自己的超时才恢复；界面会提示
- 已经传了一半的文件会留在手表上，可在手表音乐列表里删除
